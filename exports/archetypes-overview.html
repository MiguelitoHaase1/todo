Todolist — Archetype Exploration
March 2026
Eight solution directions for an intelligent task system that replaces Todoist. Informed by landscape research into Taskwarrior, MCP task servers, and AI scheduling tools.
Vision A task system that thinks alongside me — surfacing what matters most each day.
Landscape over directives Frictionless capture, rich context later Deep integration over standalone
1Custom CLI
Build from scratch in TS/Python with SQLite. Borrow Taskwarrior concepts — dependencies, hooks, JSON export — but purpose-built for your workflow.
Capture Relationships Landscape
More upfront work, but full control. No legacy baggage.
2Taskwarrior Fork
Use actual Taskwarrior as task engine. Wrap with MCP server and AI layer for /morning skill. Keep its battle-tested CLI.
Capture Relationships AI Priorities
Inherits C++ complexity. Hard to customize data model.
3MCP Server Only
The system IS an MCP server. Claude reads, writes, and reasons about tasks directly. No standalone UI — all interaction through AI sessions.
AI Priorities Reflect+Reshape Capture
Great integration, but can't capture without an AI session.
4CLI + MCP Hybrid
CLI for human interaction (capture, browse). MCP server for AI interaction (/morning reads/writes). Same SQLite, two interfaces.
Capture AI Priorities Relationships
Two interfaces to maintain. But each is focused.
5Morning Brew Ext
Extend Morning Brew directly. Add task management into the daily HTML. Tasks in Supabase. Reflection becomes reshaping interface.
Reflect+Reshape Landscape Capture
Deeply integrated but tightly coupled. No CLI capture.
6Claude Code Skill
A /tasks skill living inside Claude Code. Tasks in markdown or SQLite. Capture via /tasks add. /morning reads from the same store.
Capture AI Priorities Reflect+Reshape
No mobile web. No browsing outside Claude Code.
7Web App + API
Supabase-backed web app reusing Morning Brew's instance. REST API for /morning. Mobile-friendly UI for browsing and reshaping.
Landscape Reflect+Reshape Relationships
Most infrastructure. But gives you a real app on your phone.
8CLI + MCP + Web
CLI for capture, MCP for AI integration, thin web view on Vercel for mobile. Three surfaces, one brain. Composable by design.
All 5 JTBDs
Most pieces. But each is small, focused, composable.

Key Insight
Only two directions cover all 5 jobs
Direction 4 (CLI + MCP) and Direction 8 (CLI + MCP + Web) are the only architectures that naturally serve all five Now JTBDs. Every other direction has at least one Weak gap. The difference: #8 adds a mobile web surface for landscape browsing.
Landscape Gap
No existing tool bridges capture and reflection
Taskwarrior has the right data model (CLI + SQLite + dependencies) but no AI layer. MCP task servers exist but are agent-facing, not human-facing. The personal + self-owned + CLI + AI space is wide open.
Fork vs. Build
Taskwarrior's concepts, not its code
Taskwarrior's architecture pattern (CLI, JSON data, dependencies, hooks) is gold. But its C++ codebase makes customization hard — especially adding reflection links, AI reasoning, and MCP integration. Build from scratch, borrowing concepts.
Composability
Three small surfaces beat one big app
The strategy principle "deep integration, composable pieces" points toward direction 8. A CLI, an MCP server, and a thin web view — each independently improvable, all sharing one SQLite/Supabase brain.
